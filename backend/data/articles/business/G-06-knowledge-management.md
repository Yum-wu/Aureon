# 知识管理：团队经验沉淀与传承

## 知识管理的挑战

团队知识分为两类：**显性知识**（文档、代码、流程）和**隐性知识**（经验、直觉、人脉）。隐性知识占团队知识的 70-80%，但最难沉淀和传承。

## 知识管理体系

### 三层架构

```
L0：个人知识（笔记、收藏、经验）
L1：团队知识（Wiki、文档、Runbook）
L2：组织知识（最佳实践、培训体系、知识库）
```

### 知识生命周期

```
创建 → 审核 → 发布 → 使用 → 更新 → 归档
```

## 实践方法

### 方法一：文档即代码

将文档与代码放在同一仓库，使用 Markdown 编写，Git 版本控制：

```
docs/
├── architecture/    # 架构决策记录（ADR）
├── runbooks/        # 运维手册
├── onboarding/      # 新人引导
└── api/             # API 文档
```

### 方法二：ADR（架构决策记录）

```markdown
# ADR-001：选择 Qdrant 作为向量数据库

## 状态：已接受

## 背景
需要选择向量数据库支持 Hybrid Search。

## 决策
选择 Qdrant，原因：
1. 原生支持 dense + sparse 混合检索
2. RRF 融合无需应用层处理
3. INT8 量化支持，内存效率高

## 后果
- 正面：统一架构，无需 Elasticsearch + Qdrant 双系统
- 负面：Qdrant Cloud 成本，团队需学习新工具
```

### 方法三：Runbook

运维手册记录常见问题的处理步骤：

```markdown
# Runbook：DashScope API 限流

## 症状
- RAG 查询延迟突然升高
- 日志中出现 429 状态码

## 处理步骤
1. 确认 DashScope API 限流：检查日志中 429 错误频率
2. 启用降级：设置 `RERANK_ENABLED=false`
3. 通知团队：在 Slack #incidents 频道发消息
4. 监控恢复：等待 API 限流解除
5. 关闭降级：恢复 `RERANK_ENABLED=true`
```

### 方法四：知识分享会

定期举办知识分享会（Tech Talk），每次 30 分钟：

- 频率：每两周一次
- 主题：技术选型、踩坑经验、最佳实践
- 记录：录屏 + 文字总结存入 Wiki

## 关键事实

1. **隐性知识占团队知识的 70-80%**，但最难沉淀和传承，需要刻意设计知识管理流程
2. **文档即代码**将文档与代码放在同一仓库，Markdown 编写 + Git 版本控制，确保文档与代码同步
3. **ADR（架构决策记录）**记录重要技术决策的背景、决策和后果，防止"为什么这样做"的知识流失
4. **Runbook**记录常见问题的处理步骤，确保新人也能处理线上故障
5. **知识分享会**每两周一次，30 分钟技术分享 + 录屏存档，是隐性知识显性化的有效方式
