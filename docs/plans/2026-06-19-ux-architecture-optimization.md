### 3.2 SQLite → PostgreSQL 迁移

**目标**：新建 PostgreSQL 表结构，使用 `asyncpg` 原生驱动。现有 SQLite 数据不迁移，新数据走 PostgreSQL。

**新增依赖**：`pip install asyncpg`

**Railway 配置**：Railway 提供 PostgreSQL 托管，添加 `DATABASE_URL` 环境变量。

**新建文件**：
- `backend/app/database/`
  - `__init__.py`
  - `connection.py`：asyncpg 连接池管理（lifespan 初始化/关闭）
  - `schema.sql`：表结构 DDL
  - `migrations/`：迁移脚本

**表结构**（覆盖当前 SQLite 存储的所有数据）：

```sql
-- 消息记录（L0）
CREATE TABLE messages (
    id BIGSERIAL PRIMARY KEY,
    session_id VARCHAR(64) NOT NULL,
    role VARCHAR(16) NOT NULL,
    content TEXT NOT NULL,
    tokens INT DEFAULT 0,
    tool_name VARCHAR(128),
    tool_args TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    tenant_id VARCHAR(64) DEFAULT 'default'
);
CREATE INDEX idx_messages_session ON messages(session_id, created_at);

-- 原子事实（L1）
CREATE TABLE atoms (
    id BIGSERIAL PRIMARY KEY,
    session_id VARCHAR(64) NOT NULL,
    subject VARCHAR(256) NOT NULL,
    predicate VARCHAR(256) NOT NULL,
    object TEXT NOT NULL,
    message_id BIGINT,
    confidence REAL DEFAULT 0.5,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    tenant_id VARCHAR(64) DEFAULT 'default'
);
CREATE INDEX idx_atoms_session ON atoms(session_id);

-- 用户表
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    name VARCHAR(128),
    password_hash VARCHAR(256) NOT NULL,
    role VARCHAR(16) DEFAULT 'viewer',
    tenant_id VARCHAR(64) DEFAULT 'default',
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 审计日志
CREATE TABLE audit_logs (
    id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(64),
    action VARCHAR(64) NOT NULL,
    resource VARCHAR(128),
    detail TEXT,
    ip_address VARCHAR(45),
    tenant_id VARCHAR(64) DEFAULT 'default',
    created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_audit_tenant ON audit_logs(tenant_id, created_at);
```

**迁移策略**：
- 阶段三期间：新数据走 PostgreSQL，SQLite 数据保留但不再写入
- 同步层保留 1-2 个版本作为 fallback，通过配置开关切换
- 验证稳定后移除同步 SQLite 层

**验证**：`python -m pytest tests/ -v` 全部通过，手动验证聊天记忆、用户管理、审计日志。

### 3.3 LangFuse Prompt Management

**目标**：全部提示词迁移至 LangFuse，启动时预加载到内存，运行时零 LangFuse 依赖。

**迁移范围**（全部）：
- `QA_SYSTEM_PROMPT`（中文）
- `QA_SYSTEM_PROMPT_EN`（英文）
- `_QUERY_TYPE_INSTRUCTIONS`
- `_CONTEXTUAL_PROMPT_TEMPLATE`
- Agent 系统提示词（`app/agent/` 目录中的）

**架构设计**：
```
启动时:
  lifespan() → init_prompt_manager() → 从 LangFuse 预加载所有 prompt → 存入内存 dict

运行时:
  get_prompt("qa_system_prompt_zh") → 从内存读取 → 零延迟
  LangFuse 不可用 → fallback 到代码中硬编码的默认值
```

**新建文件**：
- `backend/app/observability/prompt_manager.py`
  - `init_prompt_manager()`：启动时调用，从 LangFuse 加载所有 prompt
  - `get_prompt(name: str, fallback: str = "") -> str`：从内存读取
  - `refresh_prompts()`：手动刷新（管理接口）

**修改文件**：
- `backend/app/startup/lifespan.py`：调用 `init_prompt_manager()`
- `backend/app/rag/generator.py`：`QA_SYSTEM_PROMPT` 改为 `get_prompt("qa_system_prompt_zh", QA_SYSTEM_PROMPT_DEFAULT)`
- `backend/app/agent/`：Agent 系统提示词同理

**LangFuse 控制台配置**：
- 在 LangFuse 创建对应名称的 Prompt 对象
- 版本化管理，支持回滚

**验证**：LangFuse 可用时预加载成功，不可用时 fallback 到默认值，测试全部通过。
